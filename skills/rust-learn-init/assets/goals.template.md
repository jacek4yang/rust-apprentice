# Goals

What the learner wants to be able to do or to build. These are preserved verbatim, because a goal a mentor takes
seriously is a goal the learner pursues, and a goal a mentor dismisses tends to be abandoned.

Each goal gets a route file in `plans/` once work begins on it. A goal with no route yet is not a problem — it is
a direction.

## Parked

Goals the learner set aside. Keep them; do not delete. Add the date and a one-line reason.

## Achieved

Move goals here when they are done, with the date. This section is one of the most useful things a long-running
workspace contains, and it is worth showing the learner occasionally.

## Notes

- A goal far above the learner's current level is recorded here in full and given a route, never refused.
- If a goal requires hardware, accounts or access the learner does not have, say so plainly and record the
  nearest achievable version alongside it.
- When a project is abandoned, move its goal to Parked rather than deleting it. Reasons are worth remembering:
  too large, too dull, and beyond current level call for different corrections.
